# 시나리오 가이드라인

훈련 통화에 쓰는 시나리오는 `ai/scenarios/library.py`에 **고정으로** 들어 있습니다.
통화를 걸 때 그중 하나를 무작위로 고를 뿐, LLM을 부르지 않습니다.
통화 중 실시간 응답만 API 키를 씁니다.

이 문서는 두 가지를 정합니다.

1. 고정 시나리오를 새로 쓰거나 고칠 때 지켜야 할 것
2. `DYNAMIC_SCENARIO=true`로 LLM에게 시나리오를 맡길 때의 생성 규칙

## 시나리오는 대본이 아니라 가이드라인이다

통화 중 문장은 매번 실시간 LLM이 새로 씁니다. 고정 시나리오가 정하는 것은 재료입니다.

| 시나리오가 고정하는 것 | 실시간 LLM이 정하는 것 |
| --- | --- |
| 인물, 기관, 사건, 시각, 금액 | 이번 턴에 실제로 할 말 |
| 목표와 진행 단계 | 상대 답변에 맞춘 순서와 강약 |
| 의심·거부·종료 의사에 대한 받아치기 방향 | 그 방향을 담은 구체적 문장 |
| 말의 길이와 결(퓨샷 예시) | 어휘와 문장 구조 |

그래서 `turn_plan`과 `objection_handling`은 대사 원문이 아니라 **행동 지시**로 씁니다.
대사를 그대로 박아 두면 LLM이 그걸 낭독해서 대화가 죽습니다.

## 고정 시나리오 한 편의 구성

`ai/scenarios/playbook.py`의 `Playbook`이 한 편입니다.

| 필드 | 쓰임 |
| --- | --- |
| `role` | 시스템 프롬프트의 `[역할]`. 누구이고 어떤 태도인지 한두 문장 |
| `opening_line` | 전화 연결 직후 나가는 고정 인사. LLM을 거치지 않습니다 |
| `incident` | 통화 내내 바뀌면 안 되는 사건. 시각·대상·금액을 한글 말로 못 박습니다 |
| `goal` | 사기범이 통화에서 얻으려는 것 |
| `turn_plan` | 진행 단계. 명령형 한 문장씩 |
| `objection_handling` | 의심·거부·화·종료 의사에 대한 대응 방향 |
| `examples` | 퓨샷. 말의 길이와 결을 이걸로 가르칩니다 |
| `quick_replies` | LLM 없이 즉답하는 고정 문장. `ai/scenarios/reflex.py`의 트리거 이름을 씁니다 |
| `hangup_line` | 두 번째 종료 의사에 던지는 마지막 한 문장 |
| `tactics` / `red_flags` / `ideal_trainee_response` | 통화 후 리포트 채점 기준 (`report_service._scenario_report_note`) |

`quick_replies`의 답은 대화 어느 시점에 나와도 어색하지 않아야 합니다.
한 통화에서 트리거당 한 번만, 전체로는 `CALL_REFLEX_BUDGET`번까지만 쓰입니다.

## 반드시 지킬 것

- 기관명은 반드시 가상으로 만든다.
- 계좌번호, 카드번호, 주민등록번호, 비밀번호, 인증번호를 생성하지 않는다.
- 전화번호, URL, 앱 이름, 패키지명, 다운로드 안내를 생성하지 않는다.
- 금액은 숫자가 아닌 한글 말투로만 표현한다. 여섯 자리 이상 숫자를 쓰지 않는다.
- 실제 은행, 카드사, 공공기관, 수사기관, 기업 이름을 사용하지 않는다.
- AI, 모델, 프롬프트, 훈련, 시뮬레이션이라는 단어를 상담원 대사에 넣지 않는다.
- 송금이나 앱 설치를 유도하더라도 구체적인 번호·주소·앱 정보는 제시하지 않는다.
- 상담원 대사는 짧고 자연스러운 한국어 문장으로 만든다. 한 응답은 문장 둘까지.

위 규칙은 `backend/tests/test_scenario_library.py`가 `generator.py`의 정규식
(`_SPOKEN_META`, `_REAL_ORGS`, `_UNSAFE_TOKEN`)으로 실제로 검사합니다.
시나리오를 추가하면 그 테스트가 새 시나리오도 자동으로 검사합니다.

## 세트 전체의 품질

- 사건 유형, 기관 유형, 말투, 압박 방식이 다른 시나리오와 겹치지 않게 한다.
- 난이도(하·중·상)를 골고루 둔다.
- `red_flags`는 `turn_plan`에서 실제로 드러나는 위험만 적는다.
- `ideal_trainee_response`는 그 위험에 대응하는 행동을 적는다.

현재 다섯 편은 기관사칭형(중), 대출사기형(하), 결제사칭형(하),
지인사칭형(중), 수사기관사칭형(상)입니다.

## 동적 생성 (선택)

`DYNAMIC_SCENARIO=true`로 두면 매 통화 전에 `ai/scenarios/generator.py`가
LLM으로 시나리오를 새로 씁니다. 생성 한 번과 검수 한 번이 한 세트이고,
검수 점수가 팔십 점 미만이면 실패 사유를 되먹여 최대 세 번까지 다시 만듭니다.
전화가 울리기까지 그 왕복을 전부 기다리므로 기본값은 꺼져 있습니다.

동적으로 만든 시나리오에는 `quick_replies`와 `hangup_line`이 없습니다.
사건이 매번 달라져서 고정 문장이 대화와 어긋날 수 있기 때문입니다.
즉답 경로 없이 모든 턴이 LLM으로 갑니다.

동적 생성에도 위 "반드시 지킬 것"이 그대로 적용되며, 생성 규칙은 다음과 같습니다.

- 기존 시나리오의 위험 유형은 유지하되, 인물·사건·말투·대화 흐름을 다르게 만든다.
- 상대방이 의심하거나 거절하거나 통화를 끊으려 할 때도 자연스럽게 대응하도록 흐름을 만든다.
- 한 통화 안에서는 사건의 세부 정보와 인물 설정을 일관되게 유지한다.
- 첫 대사는 이미 전화가 연결된 상황에서 사건을 바로 설명한다.
- 대화 흐름은 최소 네 단계로 구성한다.
- `turn_plan`은 문자열 배열이다. `{"turn": 1, "message": "..."}` 객체 배열을 쓰지 않는다.
- `ideal_trainee_response`는 문자열 하나다. 배열로 주지 않는다.
- `difficulty`는 `하`, `중`, `상`만 사용한다.
