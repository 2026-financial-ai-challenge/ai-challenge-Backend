# 통화 하네스 — AI가 통제에서 벗어나지 않게

## 한 줄 결론

**프롬프트만으로는 통제가 보장되지 않습니다.** 프롬프트는 모델에게 "부탁"하는 것이고,
전화에서는 한 번 나간 말을 되돌릴 수 없습니다. 그래서 같은 규칙을 **코드로 한 번 더**
강제합니다. 프롬프트는 1층, 코드가 2·3층입니다.

```
1층  프롬프트        SAFETY_RULES + 시나리오       (요청)        ai/safety.py, ai/scenarios/playbook.py
2층  OutputGuard     매 문장, TTS 직전             (차단·수정)    ai/harness.py
3층  CallMonitor     매 턴, 훈련자·상담원 양쪽      (교정·종료)    ai/harness.py
(4층) 사후 감사       통화 후 전사 검토              (기록·개선)    report_service + 아래 "권장" 참고
```

2·3층은 정규식과 카운터라 턴당 수 마이크로초입니다. **실시간 경로에 감독 LLM을 두지 않은
이유**가 이것입니다. 감독 LLM을 매 턴 부르면 그 왕복이 곧 무음이 됩니다.

## 프롬프트로 할 수 있는 것 / 없는 것

| 목적 | 프롬프트로 | 코드로 | 이 저장소에서 |
| --- | --- | --- | --- |
| 말투·길이·역할 유지 | **잘 됨** (퓨샷이 지시문보다 강함) | 문장 수 상한 정도 | playbook 퓨샷 + `CALL_MAX_SENTENCES` |
| 실명 기관 금지 | 대체로 됨 | **확실히 됨** | `_REAL_ORGS` 차단 |
| 비밀번호·인증번호 요구 금지 | 대체로 됨, 탈옥에 약함 | **확실히 됨** | `secret_request` 차단 (단, "저희는 절대 안 여쭙니다"는 통과) |
| 계좌·전화번호·URL 발화 금지 | 흔들림 (숫자를 지어냄) | **확실히 됨** | `sanitize_spoken_text` 치환 |
| "저는 AI입니다" 금지 | 흔들림 (훈련자가 캐물으면) | **확실히 됨** | `persona_break` 차단 |
| 같은 말 반복 방지 | 약함 | 감지 후 다음 턴 교정 | 반복 감지 → `[감독 지시]` 주입 |
| 훈련자가 실제 카드번호를 읽음 | **불가** (모델은 오히려 받아 적음) | 감지 → 역할 안에서 제지 | "번호는 말씀하지 마십시오" → 2회면 종료, 전사에서 숫자 삭제 |
| 훈련자의 실제 위급 상황 | **불가** | 감지 → 역할 해제·종료 | 훈련 전화였음을 밝히고 119 안내 |
| 시나리오 이탈(엉뚱한 사건) | 퓨샷·사건 고정으로 대체로 됨 | 부분적 | 대본 모드(`CALL_SCRIPT_MODE=on`)가 가장 강함 |

**프롬프트를 쓸 때의 가이드라인**

1. **금지 목록보다 예시.** "~하지 마라"를 늘릴수록 답이 길어지고 규칙을 되뇌는 말투가 됩니다.
   원하는 말을 퓨샷으로 보여 주고, 금지는 안전 규칙만 남깁니다.
2. **고정 부분을 앞에.** 안전 규칙과 말투 규칙은 모든 시나리오에서 바이트 단위로 같게 두어
   프리픽스 캐시가 적중하게 합니다.
3. **교정은 시스템 프롬프트에 합칩니다.** 두 번째 system 메시지를 추가하면 일부 클라이언트
   (clawops의 AnthropicLLM 등)는 마지막 것만 남겨 **시나리오 프롬프트 전체가 사라집니다.**
   `GuardedLLM`은 교정을 기존 system 메시지 끝에 `[감독 지시]` 블록으로 붙입니다.
4. **교정은 1회용.** 다음 턴에만 넣고 지웁니다. 쌓아 두면 프롬프트가 불어나 지연이 늘고
   모델이 교정문을 낭독합니다.
5. **프롬프트가 지킬 수 없는 건 프롬프트에 맡기지 않습니다.** 위 표에서 "불가"인 항목은
   반드시 코드로 둡니다.

## 각 층이 실제로 하는 일

### OutputGuard (문장 단위)

`GuardedLLM`이 LLM 토큰을 문장 끝(`.?!`)까지만 모았다가 검사합니다. 파이프라인이 원래
문장 단위로 TTS에 넘기므로 **추가 지연이 없습니다.**

- **버림:** 역할 이탈(AI·훈련·시뮬레이션·프롬프트…), 실명 기관, 비밀정보 요구
- **고침:** URL·전화번호·6자리 이상 숫자 → "안내 번호", 마크다운·괄호 지문 제거
- **자름:** 한 턴 최대 `CALL_MAX_SENTENCES`(기본 3) 문장

한 턴의 문장이 전부 버려지면 기존 `stall_line`("다시 말씀드립니다" 류)이 나갑니다. 무음이 되지 않습니다.

### CallMonitor (통화 단위)

| 신호 | 동작 |
| --- | --- |
| 훈련자가 6자리 이상 숫자를 말함 (1회) | 역할 안에서 제지: "번호는 말씀하지 마십시오." 전사·히스토리에서 숫자 삭제 |
| 같은 행동 2회 | 역할 해제 후 종료 (`SAFETY_EXIT_LINE`) |
| 호흡 곤란·가슴 통증·자해 표현·119 | 즉시 역할 해제 후 종료 |
| 가드 위반 누적 `CALL_GUARD_MAX_VIOLATIONS`(기본 3) | 역할 유지한 채 `hangup_line`으로 종료 |
| 상담원이 직전과 같은 말 반복 | 다음 턴에 "다른 표현으로 한 단계 더" 교정 주입 |

"무서워요", "어떡해요", "경찰에 신고할게요"는 **종료 신호가 아닙니다.** 시나리오가 끌어내려는
반응이라 여기서 끊으면 훈련의 가장 중요한 순간을 잘라 버립니다. 테스트가 이 경계를 고정합니다
(`backend/tests/test_harness.py`).

모든 판정은 `HARNESS {...}` 경고 로그로 남습니다.

## 권장: 4층 사후 감사 (아직 코드 없음)

실시간 경로 밖이라면 감독 LLM이 유용합니다.

- 통화가 끝난 뒤 전사 전체를 LLM에 넘겨 "안전 규칙 위반, 사건 설정 이탈, 비현실적 대사"를
  점수화하고, `HARNESS` 로그와 함께 저장합니다.
- 주 1회 위반 문장을 모아 2층 정규식과 시나리오 퓨샷을 보강합니다.
- 리포트 생성(`report_service`)이 이미 통화 후 LLM을 부르므로, 같은 호출에 감사 항목을 추가하는
  것이 가장 싼 방법입니다.

## 적용 범위

- **파이프라인 경로(Deepgram → LLM → ElevenLabs)**: 2·3층 모두 적용.
- **Realtime 폴백 경로**(`_make_realtime_agent`, Deepgram/ElevenLabs 키가 없을 때):
  음성→음성이라 텍스트를 가로챌 지점이 없어 **1층만 적용됩니다.** 방안 C로 갈 때 가장 먼저
  따져야 할 제약입니다(docs/script-mode.md).
