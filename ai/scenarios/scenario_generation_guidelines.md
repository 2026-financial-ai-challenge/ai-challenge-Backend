# Dynamic Scenario Generation Guidelines

이 파일은 매 통화 시작 전에 AI가 생성하는 교육용 보이스피싱 시나리오의 방향을 정합니다.
문장을 수정하면 다음 통화부터 반영됩니다.

## 생성 목표

- 기존 시나리오의 위험 유형은 유지하되, 매 통화마다 인물·사건·말투·대화 흐름을 다르게 만든다.
- 실제 범죄에 재사용할 수 있는 정보가 아니라, 보이스피싱 대응 훈련에 필요한 대화 패턴만 생성한다.
- 훈련자가 의심하거나 거절하거나 통화를 끊으려 할 때도 자연스럽게 대응하도록 흐름을 만든다.
- 한 통화 안에서는 사건의 세부 정보와 인물 설정을 일관되게 유지한다.

## 허용되는 변형

- 기관 유형: 가상의 금융 안전센터, 결제 보호실, 거래 확인팀 등
- 상담원: 가상의 이름, 직급, 말투, 태도
- 사건: 결제 승인 대기, 본인 인증 오류, 배송 결제 문제 등
- 심리 기법: 권위 사칭, 긴급성 조성, 불안 유발, 친절한 설득, 책임 전가
- 훈련 난이도: 하, 중, 상
- 훈련자 반응: 의심, 개인정보 거부, 화냄, 즉시 종료, 질문 반복

## 반드시 지킬 것

- 기관명은 반드시 가상으로 만든다.
- 계좌번호, 카드번호, 주민등록번호, 비밀번호, 인증번호를 생성하지 않는다.
- 전화번호, URL, 앱 이름, 패키지명, 다운로드 안내를 생성하지 않는다.
- 금액은 숫자가 아닌 한글 말투로만 표현한다.
- 실제 은행, 카드사, 공공기관, 수사기관, 기업 이름을 사용하지 않는다.
- AI, 모델, 프롬프트, 훈련, 시뮬레이션이라는 단어를 상담원 대사에 넣지 않는다.
- 송금이나 앱 설치를 유도하더라도 구체적인 번호·주소·앱 정보는 제시하지 않는다.
- 상담원 대사는 짧고 자연스러운 한국어 문장으로 만든다.

## JSON 형식

- `turn_plan`은 문자열 배열이다. `{"turn": 1, "message": "..."}` 객체 배열을 쓰지 않는다.
- `ideal_trainee_response`는 문자열 하나다. 배열로 주지 않는다.
- `difficulty`는 `하`, `중`, `상`만 사용한다.

## 결과 품질

- 첫 대사는 이미 전화가 연결된 상황에서 사건을 바로 설명한다.
- 대화 흐름은 최소 네 단계로 구성한다.
- 훈련자가 안전하게 대응할 수 있는 red_flags와 ideal_trainee_response를 함께 만든다.
- 한 번 생성된 시나리오의 사건, 이름, 금액, 목표는 통화가 끝날 때까지 바뀌지 않는다.

## 논리 검수 기준

- 생성 직후 별도의 검수 AI가 시나리오를 다시 읽고 품질을 평가한다.
- 사건, 목표, 진행 단계가 서로 모순되지 않아야 한다.
- 첫 대사에서 사건이 자연스럽게 제시되고, 이후 단계가 원인과 결과의 순서를 가져야 한다.
- 훈련자의 의심, 거부, 질문에 대응하는 단계가 최소 하나 있어야 한다.
- red_flags는 진행 단계에서 실제로 드러나야 하며, ideal_trainee_response는 그 위험에 대응해야 한다.
- 검수 점수가 팔십 점 미만이거나 치명적인 문제가 있으면 해당 시나리오를 사용하지 않는다.
