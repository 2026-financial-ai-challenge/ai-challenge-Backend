# 시나리오 가이드라인

훈련 통화에 쓰는 시나리오는 `ai/scenarios/library.py`에 **고정으로** 들어 있습니다.
통화를 걸 때 그중 하나를 무작위로 고를 뿐, LLM을 부르지 않습니다.
통화 중 실시간 응답만 API 키를 씁니다.

이 문서는 고정 시나리오를 새로 쓰거나 고칠 때 지켜야 할 것을 정합니다.
실제 사기 수법과 통계 근거는 [`docs/research/voice-phishing-patterns.md`](../../docs/research/voice-phishing-patterns.md)에 있습니다.

## 시나리오는 대본이 아니라 가이드라인이다

통화 중 문장은 매번 실시간 LLM이 새로 씁니다. 고정 시나리오가 정하는 것은 재료입니다.

| 시나리오가 고정하는 것 | 실시간 LLM이 정하는 것 |
| --- | --- |
| 인물, 기관, 사건, 시각, 금액 | 이번 턴에 실제로 할 말 |
| 목표와 진행 단계 | 상대 답변에 맞춘 순서와 강약 |
| 의심·거부·종료 의사에 대한 받아치기 방향 | 그 방향을 담은 구체적 문장 |
| 말의 길이와 결(퓨샷 예시) | 어휘와 문장 구조 |

그래서 `turn_plan`과 `objection_handling`은 대사 원문이 아니라 **행동 지시**로 씁니다.
대사를 그대로 박아 두면 LLM이 그걸 낭독해서 대화가 죽습니다.

## 고정 시나리오 한 편의 구성

`ai/scenarios/playbook.py`의 `Playbook`이 한 편입니다.

| 필드 | 쓰임 |
| --- | --- |
| `role` | 시스템 프롬프트의 `[역할]`. 누구이고 어떤 태도인지 한두 문장 |
| `opening_line` | 전화가 연결되면 AI가 토씨 하나 바꾸지 않고 말하는 첫 마디 |
| `incident` | 통화 내내 바뀌면 안 되는 사건. 시각·대상·금액을 한글 말로 못 박습니다 |
| `goal` | 사기범이 통화에서 얻으려는 것 |
| `turn_plan` | 진행 단계. 명령형 한 문장씩 |
| `objection_handling` | 의심·거부·화·종료 의사에 대한 대응 방향 |
| `examples` | 퓨샷. 말의 길이와 결을 이걸로 가르칩니다 |
| `quick_replies` | 트리거 이름과 고정 답. 통화 지시문에는 들어가지 않고, 녹취에서 AI 화자를 가려낼 때만 씁니다(`ai/transcript.py`) |
| `hangup_line` | 끊으려 할 때 던지는 경고 한 문장. 전화(매니지드 에이전트)에서는 첫 번째 종료 의사에 붙잡으며 말하고 두 번째에는 말없이 끊습니다. 종료 도구와 같은 차례에 한 말은 재생 전에 끊기기 때문입니다. |
| `giveup_line` | 거절했을 때 한 번 하는 포기 경고. 인물에 맞는 손해나 불이익으로 압박하고, 훈련생이 해야 할 정답 행동(공식 번호로 확인 등)을 말하지 않습니다. 이 말 뒤 또 거절하거나 끊겠다고 하면 말없이 끊습니다 |
| `handoff_line` | 목표의 마지막 요구(돈 옮기기·보내기, 알려 준 번호로 전화 걸기, 앱 설치하기·채팅방 들어오기)를 승낙받으면 하는 넘김 말. "담당이 다시 연락한다"처럼 통화가 끝나도 어색하지 않게 씁니다. 이 말 뒤 상대가 한 번 더 말하면 말없이 끊습니다 |
| `tactics` / `red_flags` / `ideal_trainee_response` | 통화 후 리포트 채점 기준 (`report_service._scenario_report_note`) |
| `progression` / `script` | 단계별 대사와 훈련자 의도별 답변. 통화 지시문에는 `progression` 전체가 [단계별 대사 예시]로, `script`는 의도별 첫 줄만 [상대 반응별 받아치기 예시]로 들어갑니다 |

통화 때 AI에게 실제로 가는 지시문은 `python -m ai.managed_agent context --scenario <id>`로 볼 수 있습니다.
`quick_replies`와 `script`의 두 번째 줄은 고쳐도 통화가 바뀌지 않습니다.

## 반드시 지킬 것

- 기관명은 반드시 가상으로 만든다.
- 계좌번호, 카드번호, 주민등록번호, 비밀번호, 인증번호를 생성하지 않는다.
- 전화번호, URL, 앱 이름, 패키지명, 다운로드 안내를 생성하지 않는다.
- 금액은 숫자가 아닌 한글 말투로만 표현한다. 여섯 자리 이상 숫자를 쓰지 않는다.
- 시각은 "이십 분 전", "두 시간 뒤"처럼 상대 시각으로만 쓴다. "오후 네 시" 같은 고정 시각은 그 시각이 지난 뒤 걸린 통화에서 거짓이 된다. 지난 일("어제 오후 두 시")은 괜찮다. `ai/tests/test_scenario_text.py`가 검사한다.
- 실제 은행, 카드사, 공공기관, 수사기관, 기업 이름을 사용하지 않는다.
- AI, 모델, 프롬프트, 훈련, 시뮬레이션이라는 단어를 상담원 대사에 넣지 않는다.
- 송금이나 앱 설치를 유도하더라도 구체적인 번호·주소·앱 정보는 제시하지 않는다.
- 상대가 계좌번호·연락처·주소를 달라고 할 때 미루는 방향을 `objection_handling`에 한 줄 넣는다.
  빠지면 모델이 숫자를 지어내거나 역할을 깰 수 있다.
- 상담원 대사는 짧고 자연스러운 한국어 문장으로 만든다. 한 응답은 문장 둘까지.

위 규칙은 `backend/tests/test_scenario_library.py`가 `ai/safety.py`의 정규식
(`SPOKEN_META`, `REAL_ORGS`, `UNSAFE_TOKEN`)으로 실제로 검사합니다.
시나리오를 추가하면 그 테스트가 새 시나리오도 자동으로 검사합니다.

## 대화가 막히지 않게

- 예/아니요로 갈리는 질문(신청하셨나요, 결제하셨나요, 대출이 있나요, 예금이 있나요)은 양쪽 대답 모두 목표로 이어지게 `turn_plan`이나 `objection_handling`에 적는다. 한쪽만 적으면 다른 대답에서 AI가 스스로 사기를 그만두거나, 동의를 받지 않고 넘김 말을 한다.
- 상대가 할 말을 정해 주지 않는다. "~하겠다고만 해 주세요" 대신 "오늘 안에 내실 거죠?"처럼 묻는다. 정해 주면 AI가 그 말을 들을 때까지 같은 요구를 되풀이한다.

## 세트 전체의 품질

- 사건 유형, 기관 유형, 말투, 압박 방식이 다른 시나리오와 겹치지 않게 한다.
- 난이도(하·중·상)를 골고루 둔다.
- `red_flags`는 `turn_plan`에서 실제로 드러나는 위험만 적는다.
- `ideal_trainee_response`는 그 위험에 대응하는 행동을 적는다.

현재 다섯 편은 기관사칭형(중), 대출사기형(하), 투자사기형(하),
배송원사칭형(중), 수사기관사칭형(상)입니다.

- 택배 사칭은 실제로는 대부분 문자 링크(스미싱)라 전화 시나리오로 쓰지 않습니다.
- 가족 사칭은 실제 가족 목소리가 아니면 오히려 이질적이라, 모르는 사람이 거는 카드 배송원 사칭을 씁니다.
- 바꾼 시나리오의 예전 id는 `_ALIASES`로 지금 id에 이어 둡니다.
- 투자 사기는 `docs/research/voice-phishing-patterns.md`의 작업 정의(법적 정의 기준)에서는 빠져 있지만, 피해가 빠르게 늘어 훈련 대상에 넣었습니다.

## 새 시나리오를 늘리는 방법

통화마다 LLM이 시나리오를 새로 쓰지 않습니다. 사람이 검토하고
테스트가 금지어를 검사한 문장만 통화에 나가야 하기 때문입니다.

같은 대본이 반복되는 문제는 **편수를 늘려서** 풉니다.

1. LLM에게 이 문서를 주고 새 플레이북 초안을 받는다 (통화 경로 밖, 작성 도구로만 사용).
2. 사람이 사건·수법·대사를 다듬어 `library.py`에 넣는다.
3. `python -m pytest ai/tests backend/tests/test_scenario_library.py`로 금지어와 형식을 검사한다.
4. `python -m ai.managed_agent context --scenario <id>`로 통화 지시문이 4,000자 안에 예시까지 다 들어가는지 본다.
5. 시험 통화로 확인한다. 에이전트는 시나리오별로 하나씩 있으므로, 새 시나리오는 `CARTESIA_VOICES`에 목소리를 넣고 sync해야 한다.
