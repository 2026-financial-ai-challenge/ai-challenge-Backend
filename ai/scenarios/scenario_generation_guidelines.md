# 시나리오 가이드라인

훈련 통화에 쓰는 시나리오는 `ai/scenarios/library.py`에 **고정으로** 들어 있습니다.
통화를 걸 때 그중 하나를 골라 통화별 지시문(CallContext)으로 ClawOps 에이전트에 보냅니다(`ai/managed_agent.py`).

이 문서는 고정 시나리오를 새로 쓰거나 고칠 때 지켜야 할 것을 정합니다.
실제 사기 수법과 통계 근거는 [`docs/research/voice-phishing-patterns.md`](../../docs/research/voice-phishing-patterns.md)에 있습니다.

## 시나리오는 대본이 아니라 가이드라인이다

통화 중 문장은 매번 에이전트의 실시간 모델이 새로 씁니다. 고정 시나리오가 정하는 것은 재료입니다.

| 시나리오가 고정하는 것 | 실시간 모델이 정하는 것 |
| --- | --- |
| 인물, 기관, 사건, 시각, 금액 | 이번 턴에 실제로 할 말 |
| 목표와 진행 단계 | 상대 답변에 맞춘 순서와 강약 |
| 의심·거부·종료 의사에 대한 받아치기 방향 | 그 방향을 담은 구체적 문장 |
| 말의 길이와 결(퓨샷 예시) | 어휘와 문장 구조 |

그래서 `turn_plan`과 `objection_handling`은 대사 원문이 아니라 **행동 지시**로 씁니다.
대사를 그대로 박아 두면 모델이 그걸 낭독해서 대화가 죽습니다.

## 고정 시나리오 한 편의 구성

`ai/scenarios/playbook.py`의 `Playbook`이 한 편입니다.

| 필드 | 쓰임 |
| --- | --- |
| `id` | 통화 기록과 에이전트 이름(`spc-<id>-<방식>`)에 저장되므로 바꾸지 않습니다. 꼭 바꿔야 하면 예전 id를 `ai/scenarios/__init__.py`의 `_ALIASES`에 넣습니다 |
| `role` | 통화 지시문의 `[역할]`. 누구이고 어떤 태도인지, 반말인지 존댓말인지 한두 문장 |
| `opening_line` | 전화 연결 직후 토씨 그대로 말하는 `[첫 마디]` |
| `incident` | 통화 내내 바뀌면 안 되는 사건. 시각·대상·금액을 한글 말로 못 박습니다 |
| `goal` | 사기범이 통화에서 얻으려는 것 |
| `turn_plan` | 진행 단계. 명령형 한 문장씩 |
| `objection_handling` | 의심·거부·화·종료 의사에 대한 대응 방향 |
| `examples` | 퓨샷. 말의 길이와 결을 이걸로 가르칩니다 |
| `max_turns` | 상대 발화 기준 통화 길이. 넘기면 통화를 끝냅니다 |
| `quick_replies` | 자주 나오는 상황(누구냐, 안 들린다 등)에 대한 짧은 답. 녹취록에서 AI 화자를 찾는 기준 문장으로 씁니다(`ai/transcript.py`) |
| `hangup_line` | 상대가 처음 끊겠다고 할 때 하는 경고 한 문장. `giveup_line`을 이미 말했으면 생략하고 바로 끊고, 두 번째에는 말없이 끊습니다. 종료 도구와 같은 차례에 한 말은 재생되기 전에 끊기므로 마지막 인사로 쓰지 않습니다 |
| `giveup_line` | 거절했을 때 한 번 하는 포기 경고. 인물에 맞는 손해나 불이익으로 압박하고, 훈련생이 해야 할 정답 행동(공식 번호로 확인 등)을 말하지 않습니다. 이 말 뒤 또 거절하거나 끊겠다고 하면 말없이 끊습니다 |
| `handoff_line` | 목표의 마지막 요구(돈 옮기기·보내기, 알려 준 번호로 전화 걸기, 앱 설치하기·채팅방 들어오기)를 승낙받으면 하는 넘김 말. "담당이 다시 연락한다"처럼 통화가 끝나도 어색하지 않게 씁니다. 이 말 뒤 상대가 한 번 더 말하면 말없이 끊습니다 |
| `tactics` / `red_flags` / `ideal_trainee_response` | 통화 후 리포트 채점 기준(`report_service._scenario_report_note`) |
| `progression` / `script` | 단계별 대사 예시와 상대 반응별 받아치기 예시. 통화 지시문에 참고용으로 들어가고(`script`는 반응마다 첫 문장만), 지시문이 4,000자를 넘으면 이 순서로 빠집니다 |

## 반드시 지킬 것

- 기관명은 반드시 가상으로 만든다.
- 계좌번호, 카드번호, 주민등록번호, 비밀번호, 인증번호를 생성하지 않는다.
- 전화번호, URL, 앱 이름, 패키지명, 다운로드 안내를 생성하지 않는다.
- 금액은 숫자가 아닌 한글 말투로만 표현한다. 여섯 자리 이상 숫자를 쓰지 않는다.
- 시각은 "이십 분 전", "두 시간 뒤"처럼 상대 시각으로만 쓴다. "오후 네 시" 같은 고정 시각은 그 시각이 지난 뒤 걸린 통화에서 거짓이 된다. 지난 일("어제 오후 두 시")은 괜찮다.
- 실제 은행, 카드사, 공공기관, 수사기관, 기업 이름을 사용하지 않는다.
- AI, 모델, 프롬프트, 훈련, 시뮬레이션이라는 단어를 상담원 대사에 넣지 않는다.
- 송금이나 앱 설치를 유도하더라도 구체적인 번호·주소·앱 정보는 제시하지 않는다.
- 상대가 계좌번호·연락처·주소를 달라고 할 때 미루는 방향을 `objection_handling`에 한 줄 넣는다.
  빠지면 모델이 숫자를 지어내거나 역할을 깰 수 있다.
- 상담원 대사는 짧고 자연스러운 한국어 문장으로 만든다. 한 응답은 문장 둘까지.

시각, 금지어, 실제 기관명, 번호·주소 규칙은 `ai/tests/test_scenario_text.py`가 모든 시나리오의 모든 문장을
`ai/safety.py`의 정규식(`SPOKEN_META`, `REAL_ORGS`, `UNSAFE_TOKEN`)으로 검사합니다. 시나리오를 추가하면 자동으로 검사 대상이 됩니다.

## 세트 전체의 품질

- 사건 유형, 기관 유형, 말투, 압박 방식이 다른 시나리오와 겹치지 않게 한다.
- 난이도(하·중·상)를 골고루 둔다.
- 실제로 전화로 많이 오는 수법을 고른다. 택배 사칭(대부분 문자 링크로 온다)이나 자녀 사칭(실제 자녀 목소리가 아니면 어색하다)은 전화 훈련에 맞지 않는다.
- `red_flags`는 `turn_plan`에서 실제로 드러나는 위험만 적는다.
- `ideal_trainee_response`는 그 위험에 대응하는 행동을 적는다.

현재 다섯 편은 기관사칭형(중), 대출사기형(하), 투자사기형(하), 배송원사칭형(중), 수사기관사칭형(상)입니다.
투자사기는 근거 문서의 작업 정의(법적 정의 기준)에는 없지만 피해가 빠르게 늘어 넣었습니다.

## 새 시나리오를 늘리는 방법

시나리오는 통화마다 생성하지 않습니다. 사람이 다듬고 테스트를 통과한 시나리오만 씁니다.

1. LLM에게 이 문서를 주고 새 플레이북 초안을 받는다(통화 경로 밖에서 작성 도구로만 쓴다).
2. 사람이 사건·수법·대사를 다듬어 `library.py`에 넣는다.
3. `ai/managed_agent.py`의 `CARTESIA_VOICES`와 `LIVE_VOICES`에 목소리를 정하고, `ai/tests/test_scenario_ids.py`의 `PINNED_IDS`에 id를 넣는다.
4. `python -m pytest ai/tests`로 시각, 금지어, 통화 지시문 길이(4,000자)를 검사한다.
5. `python -m ai.managed_agent sync`로 에이전트를 만든다.
